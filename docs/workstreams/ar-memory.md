## Goal

아파트 단지 입주민이 "이 순간을 남기고 싶다"고 직접 선택했을 때만 게시물을 남기고, 같은 장소에 쌓인 여러 시점의 기록을 비교해 볼 수 있는 "추억 공유 소셜 AR"의 핵심 컨셉을 실제 AR Glass 없이 지도(단지 배치도) 기반 웹 화면으로 먼저 검증한다.

## Background

CCTV처럼 자동 기록되는 방식이 아니라, 입주민이 직접 선택해 기록을 남기고 그 장소에서만 다시 볼 수 있는 소셜 서비스를 기획 중이다. 실기기 AR 연동 이전에, 지도 위 핀 클릭 → 시간순 타임라인이라는 핵심 UX와 이웃 기반 공개범위 로직이 사용성이 있는지부터 검증하기 위해 별도 실험으로 시작한다.

## Current Direction

React 19 + TypeScript + Vite로 클라이언트 전용 프로토타입을 구현했다. Backend/DB 없이 `localStorage`에 데이터를 저장하고, 지도는 실제 지도 API 대신 인라인 SVG로 그린 단지 배치도를 사용한다. 사진/영상은 Base64 Data URL로 변환해 저장한다. 이 기술 선택은 이 Workstream의 검증 대상이며 프로젝트 전체 표준이 아니다.

## Scope

- 단지 배치도(SVG) 위 지점별 핀 표시, 카테고리(계절 풍경/아이 성장/텃밭·화단/반려동물)별 색상·아이콘 구분
- 핀 클릭 시 해당 지점 게시물의 시간순 타임라인 표시 (같은 장소·다른 시점 비교)
- 게시물 등록: 사진/영상 업로드, 카테고리 선택, 지도에서 위치(지점) 선택, 공개범위 선택
- 이웃 맺기(팔로우형) 기능과 공개범위(이웃 공개/단지 전체 공개)에 따른 노출 차등
- 좋아요, 댓글
- 실제 인증 없이 테스트 계정 2~3개를 전환하며 사용하는 로그인 대체 UI
- 데모용 시드 데이터 (테스트 계정, 이웃 관계, 지점별 시간순 게시물)

## Out of Scope

- 실제 AR 카메라 오버레이, 6DoF, 실기기 검증 (`geo-time-ar-v2` Workstream의 영역)
- 실제 인증/회원가입, 결제, 운영 배포
- Backend/DB/Object Storage 연동 (현재는 `localStorage`만 사용)
- GPS 기반 자유 좌표 — 현재는 미리 정의한 5개 지점 중 선택하는 방식

## Key Questions

- 지점을 미리 정의하는 방식과 배치도 임의 좌표에 자유롭게 핀을 찍는 방식 중 실제 서비스에 더 적합한 것은 무엇인가?
- 이웃 공개/전체 공개 2단계 공개범위로 충분한가, 더 세분화된 공개 대상 설정이 필요한가?
- `geo-time-ar-v2` Workstream의 Geo + Time 후보 조회 Backend와 이 프로토타입의 데이터 모델을 어떻게 통합할 것인가?

## Decisions

- 게시물은 위경도 자유 좌표가 아니라 미리 정의한 지점(Spot) 중 하나에 소속시킨다. 같은 장소에 기록이 안정적으로 쌓이게 하기 위함이다.
- 공개범위는 "이웃 공개"(기본값)와 "단지 전체 공개" 2단계로만 구현한다.
- 이웃 공개 게시물은 작성자 본인과, 작성자를 이웃으로 맺은 사람에게만 노출한다. 전체 공개 게시물은 이웃이 아닌 사람에게는 "더보기"로 분리해 노출한다.

## Dependencies

- Node.js (LTS), npm

## Notes for Other Teams

`geo-time-ar-v2` Workstream(goguma-salad)과 같은 "장소 기반 추억/콘텐츠" 문제를 다른 접근(지도 UI vs 실기기 AR)으로 탐색하는 병행 실험이다. 서로의 진행을 제한하지 않으며, 통합 시점에는 데이터 모델(게시물/카테고리/공개범위)과 Backend 선택지를 비교 검토한다.

## Known Issues

- Backend가 없어 계정 간 데이터가 실제로 동기화되지 않는다 (같은 브라우저의 `localStorage` 안에서만 공유됨).

- 업로드 파일 용량 제한/압축 처리가 없다.
