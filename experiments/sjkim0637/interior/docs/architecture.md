# 시스템 아키텍처

## 초기 구조

```text
Android AR 앱
  ├─ 카메라와 AR 공간 추적
  ├─ 벽·바닥 평면 인식
  ├─ TV 영역 선택
  └─ 결과 배치와 전/후 비교
          │
          │ 대표 이미지 + bbox + 카메라/평면 정보
          ▼
중간 API 서버
  ├─ Scene과 작업 상태 관리
  ├─ 이미지 및 결과 저장
  ├─ 중복 호출과 사용량 제어
  └─ AI Provider 중계
          │
          ▼
외부 이미지 편집 AI
  └─ TV 제거 + 가려진 벽 복원
```

## 개발 전략

| 방식 | 내용 | 초기 결정 |
|---|---|---|
| A | 외부 AI 이미지 편집 API | PHASE 1 우선 |
| B | 스마트폰 또는 서버의 경량 모델 | PHASE 6 검토 |
| C | 여러 촬영 화면을 이용한 자체 복원 엔진 | PHASE 7 검토 |

## 핵심 원칙

- 외부 AI는 매 프레임 호출하지 않고 사용자가 삭제를 확정한 대표 이미지에만 호출한다.
- AI 결과와 카메라 Pose, 평면 Anchor를 함께 관리해 결과가 실제 공간에서 흔들리지 않도록 한다.
- 앱은 특정 AI 업체에 직접 의존하지 않고 서버의 Provider 인터페이스를 통해 사용한다.
- 초기에는 bbox로 전체 흐름을 검증하고 정밀 마스크는 이후 개선한다.

## PHASE 1 구현 순서

1. Android 카메라와 AR 평면 인식
2. bbox 선택과 키프레임 캡처
3. API 서버 및 Mock AI
4. 앱에서 결과 수신·표시
5. PC E2E 검증
6. 실제 외부 AI 연결
7. Android 실기기 E2E 검증
