| 사진 기반 AI 인테리어 결과가 실제 공간 좌표와 연결되지 않는다 | 생성형 AI로 인테리어 이미지를 만들어 본 사용자 | 보기 좋은 이미지가 생성돼도 실제 벽·바닥 위치에서 크기와 배치를 검토하거나 카메라를 움직이며 확인하기 어렵다 | 저장소 아키텍처 검토에서 AI 결과와 Camera Pose·Plane Anchor를 함께 관리해야 한다는 기술 병목을 확인했다 | 기술 문제 |
| 사물 제거 AI의 품질과 대기시간이 일정하지 않다 | 실제 공간에서 즉시 결과를 보고 싶은 사용자 | 벽 무늬·원근이 어색하거나 처리가 오래 걸리면 신뢰와 몰입이 떨어진다 | Workstream의 핵심 질문으로 원본 벽의 색상·질감·원근 보존, Anchor 안정성, 응답시간이 명시돼 있다 | 검증 필요 |

### 우선 해결할 문제

**사용자는 기존 가구가 있는 상태에서도, 가구를 실제로 옮기지 않고 빈 공간과 새로운 배치안을 현실감 있게 비교하기 어렵다.**

선정 이유는 다음과 같습니다.

- 새 가구를 “추가”하는 것만으로는 기존 가구 교체 상황을 완전히 해결하지 못합니다.
- 기존 가구 제거 → 벽 복원 → 재배치 → 전후 비교가 하나의 짧은 시연 흐름으로 연결됩니다.
- AI 이미지 편집과 AR 공간 배치가 각각 분명한 역할을 가져 기술적 차별성을 설명하기 쉽습니다.

### B. 외부 사례 및 연구

1. **IKEA Kreativ 외부 사례**  
   IKEA는 사용자가 방을 스캔하고 기존 가구를 디지털로 지운 뒤 새 가구를 배치할 수 있도록 지원합니다. 이는 “기존 물건을 치우지 않고 빈 공간을 확인하고 싶다”는 문제가 실제 서비스에서도 다뤄지는 과제임을 보여 줍니다.  
   - [IKEA Kreativ — 기존 가구 지우기](https://www.ikea.com/us/en/customer-service/knowledge/articles/6226432c-c257-4d49-bf04-cede16cae5c5.html)
   - [IKEA Kreativ — 방을 비우지 않고 스캔하기](https://www.ikea.com/us/en/customer-service/knowledge/articles/232bfef8-22ff-4788-9dfa-e6921c22adb2.html)
   - [IKEA Kreativ 소개](https://www.ikea.com/us/en/home-design/)

2. **AR 가구 전자상거래 연구**  
   2025년 202명을 대상으로 한 연구는 AR의 상호작용성과 정보성이 실용적 가치에 영향을 주며, 만족도와 태도를 거쳐 구매 의도에 영향을 준다고 설명합니다. ROOMSHIFT의 검증 초점도 단순한 시각적 재미보다 “실제 공간에서 유용한 판단을 돕는가”에 둡니다.  
   - [Transforming furniture e-commerce: The impact of augmented reality on purchase intentions](https://profile.cpce-polyu.edu.hk/en/publications/transforming-furniture-e-commerce-the-impact-of-augmented-reality/)

3. **AR 쇼핑 경험 연구**  
   2024년 공개 연구는 AR 쇼핑 경험과 구매 의도의 관계를 다루며, 전자상거래에서 AR 경험을 활용할 실무적 필요성을 제시합니다.  
   - [The impact of AR online shopping experience on customer purchase intention](https://pmc.ncbi.nlm.nih.gov/articles/PMC11346642/)

## 3. 🎯 업무 여정맵과 병목

| 단계 | 사용자의 행동 | 현재 사용하는 방법 | 핵심 불편 | ROOMSHIFT가 바꾸는 점 |
|---|---|---|---|---|
| 1. 변화 필요 인식 | TV 교체, 소파 추가, 가구 이동을 고민 | 가족과 대화하거나 사진을 본다 | 원하는 변화가 구체화되지 않는다 | 실제 공간을 Scene으로 생성한다 |
| 2. 공간 확인 | 방 크기와 빈 벽을 측정 | 줄자, 사진, 메모 사용 | 측정값과 실제 인상이 연결되지 않는다 | 카메라와 ARCore로 벽·바닥을 인식한다 |
| 3. 기존 가구 제거 상상 | 현재 TV·소파가 없어진 모습을 상상 | 머릿속으로 추정하거나 직접 옮긴다 | **가장 큰 병목 ①: 가구 뒤 공간을 볼 수 없다** | 사용자가 TV 영역을 선택하면 AI가 TV와 그림자를 지우고 벽을 복원한다 |
| 4. 새 배치 시도 | 후보 가구와 위치를 정한다 | 쇼핑몰 사진 합성 또는 실제 이동 | **가장 큰 병목 ②: 크기·위치·동선을 현실적으로 비교하기 어렵다** | TV와 소파 프록시를 AR 공간에 배치·이동·크기 조절한다 |
| 5. 대안 비교 | 배치 A/B를 가족과 비교 | 사진 여러 장과 기억에 의존 | 비교 기준이 다르고 원상복구가 번거롭다 | 변경 전·후를 같은 화면에서 비교한다 |
| 6. 결정 | 구매 또는 실제 이동 여부 결정 | 감으로 결정 | 실패 시 반품·재배치 비용이 발생한다 | 시각적 근거를 보고 더 자신 있게 결정한다 |

### 핵심 병목

- **상상 병목:** 기존 가구가 가리고 있는 벽과 빈 공간을 확인할 수 없습니다.
- **현실성 병목:** 생성 이미지와 실제 공간의 위치·크기가 분리되어 있습니다.
- **비교 병목:** 전후 상태를 동일한 기준으로 빠르게 비교하기 어렵습니다.
- **신뢰 병목:** AI 복원 품질과 AR Anchor 안정성이 부족하면 결과를 믿기 어렵습니다.

## 4. 🎯 문제정의문(POV)

- TV·소파처럼 크고 무거운 가구를 교체하거나 재배치하려는 사람
- 온라인 가구 구매 전에 자신의 공간에서 적합성을 확인하려는 사람

## 6. 💡 최종 선택된 아이디어

### 최종 선택한 아이디어

**MISO ROOMSHIFT — AI 사물 제거와 AR 가구 재배치를 연결한 실시간 공간 리디자인 서비스**

### 선택한 이유

- 기존 AR 가구 서비스의 “새 가구 추가”를 넘어 “기존 가구 제거와 공간 복원”까지 하나의 흐름으로 연결합니다.
- AI 이미지 편집이 잘하는 벽 복원과 AR이 잘하는 실제 위치·크기 배치를 역할별로 결합합니다.
- TV 하나를 지우고 재배치하는 짧고 명확한 장면만으로 핵심 가치를 시연할 수 있습니다.
- 자체 AI 학습 없이 MISO 중심의 Workflow와 외부 AI Provider를 조합해 해커톤 기간 안에 검증할 수 있습니다.

### 핵심 기능

1. 스마트폰 카메라 기반 거실 촬영
2. ARCore 벽·바닥 평면 인식
3. 화면 터치로 TV bbox 선택
4. AI 기반 TV·그림자 제거 및 가려진 벽 복원
5. 복원 결과를 실제 벽 Anchor에 표시
6. TV와 소파 배치·이동·크기 조절
7. 변경 전·후 비교
8. 처리 상태와 실패 원인 안내

### 사용자가 얻게 되는 변화 / 기대효과

| 기존 | ROOMSHIFT 사용 후 |
|---|---|
| 기존 가구가 없어진 모습을 머릿속으로 상상 | 화면에서 빈 공간을 직접 확인 |
| 가구를 실제로 옮겨 위치를 비교 | AR에서 여러 위치를 빠르게 시험 |
| 상품 이미지와 실제 공간을 따로 판단 | 실제 공간 좌표에서 크기·배치 확인 |
| 가족마다 다른 상상으로 의견 충돌 | 같은 전후 화면을 보며 합의 |
| 불확실한 상태로 구매·재배치 | 시각적 근거를 바탕으로 결정 |

### AI가 도울 일

- 선택된 TV와 주변 그림자를 제거합니다.
- 가려져 있던 벽의 색상·질감·원근을 주변 맥락에 맞게 복원합니다.
- MISO Workflow가 사용자 의도, bbox, Scene 정보를 구조화하고 적절한 편집 Prompt를 구성합니다.
- 처리 상태와 실패 사유를 사용자에게 이해하기 쉬운 말로 안내합니다.
- 이후 단계에서는 공간 조건과 사용자 선호를 바탕으로 후보 배치안을 추천합니다.

### 필요한 지식과 데이터

- ARCore Plane Detection, Camera Pose, Anchor, World Coordinate
- 정규화 bbox `[x, y, width, height]`
- 원본 거실 Keyframe과 Camera·Plane Metadata

- AI 결과 이미지, Provider, 처리시간, 오류 정보

- 사용자 테스트의 성공 여부, 소요시간, 자연스러움·신뢰도 평가

### MISO 구성과 역할

| 구성 | 역할 |
|---|---|
| MISO 입력 Workflow | 사용자의 “TV를 지우고 다른 벽에 배치” 의도와 Scene·bbox 정보를 수집·검증 |
| MISO Prompt 구성 | 공간 맥락을 유지하면서 TV와 그림자를 제거하고 벽을 복원하도록 구조화된 편집 지시 생성 |
| MISO Tool/API 호출 | FastAPI의 Scene, Keyframe, Remove Object, Job API 순서 제어 |
| AI Provider Adapter | 개발 중에는 Mock AI, 실제 검증에서는 Gemini 이미지 편집 Provider 사용 |
| MISO 결과 설명 | 처리 중·완료·실패 상태와 다음 행동을 사용자에게 자연어로 안내 |
| MISO 검증 로그 | 입력, 처리시간, 성공·실패, 재시도 정보를 기록해 품질 개선 근거로 활용 |

> 현재 저장소에는 Mock AI와 Gemini Provider가 구현되어 있습니다. 위 MISO 역할은 해커톤 제출 구조에 맞춘 통합 Workflow 설계이며, 실제 MISO 연결 여부는 제출 전 별도로 확인해야 합니다.

### 전체 작동 흐름

1. 사용자가 Android 앱에서 새 거실 Scene을 만듭니다.
2. ARCore가 카메라를 실행하고 벽·바닥 평면을 인식합니다.
3. 사용자가 TV 영역을 bbox로 선택합니다.
4. 앱이 대표 Keyframe, bbox, Camera Pose, Plane Anchor를 FastAPI에 전송합니다.
5. MISO Workflow가 요청값을 검사하고 이미지 편집 Prompt를 구성합니다.
6. Provider Adapter가 Mock AI 또는 Gemini에 TV 제거·벽 복원을 요청합니다.
7. 앱은 Job 상태를 `queued → processing → succeeded | failed`로 조회합니다.
8. 성공하면 복원 이미지를 받아 원래 벽 Anchor에 표시합니다.
9. 사용자가 TV와 소파를 배치·이동·크기 조절합니다.
10. 변경 전·후 화면을 비교하고 배치 의사결정을 내립니다.

## 12. 🚀 스토리텔링(솔루션 설명서)

### 12-1. 문제의 시작

거실의 TV를 다른 벽으로 옮기고 소파를 새로 놓고 싶다고 가정해 보겠습니다. 온라인 쇼핑몰에는 멋진 상품 사진이 많고, AR로 가구를 추가하는 서비스도 있습니다. 하지만 현재 TV가 사라졌을 때 뒤의 벽이 어떻게 보일지, TV를 다른 벽으로 옮겼을 때 동선이 괜찮을지, 새 소파와 함께 놓았을 때 공간이 답답하지 않을지는 여전히 사용자가 머릿속으로 상상해야 합니다. 직접 가구를 옮겨 보려면 시간과 힘이 들고, 결과가 마음에 들지 않으면 다시 원상복구해야 합니다.

### 12-2. 우리의 관점

우리는 문제를 “새 가구를 화면에 올리는 것”으로만 보지 않았습니다. 진짜 어려움은 **기존 가구를 치운 뒤의 공간을 확인하고, 그 빈 공간에서 새로운 배치를 현실적으로 비교하는 것**이라고 정의했습니다.

### 12-3. 해결 방법

MISO ROOMSHIFT는 스마트폰 카메라, AI 이미지 편집, AR 공간 배치를 하나의 여정으로 연결합니다.

사용자가 거실을 촬영하고 TV 영역을 선택하면, MISO Workflow가 Scene 정보와 사용자 의도를 구조화합니다. 이미지 편집 AI는 TV와 주변 그림자를 제거하고 가려져 있던 벽을 자연스럽게 복원합니다. 앱은 이 결과를 단순한 새 이미지로 보여 주는 데서 끝나지 않고, Camera Pose와 Plane Anchor를 이용해 실제 벽 위치에 연결합니다. 그 위에서 사용자는 TV를 다른 벽으로 옮기고 소파를 추가해 위치와 크기를 조절한 뒤 변경 전과 변경 후를 비교합니다.

### 12-4. MISO와 AI의 역할

MISO는 사용자 요청을 이해하고 앱과 서버, 이미지 편집 Provider 사이의 순서를 조율하는 역할을 맡습니다. “TV와 그림자를 제거하되 주변 벽의 색상·질감·원근을 유지한다”는 편집 지시를 구성하고, Job 상태를 추적하며, 실패 시 사용자가 이해할 수 있는 안내를 제공합니다. 실제 픽셀 편집은 교체 가능한 외부 AI Provider가 수행합니다. 이렇게 역할을 분리하면 특정 모델에 종속되지 않고 Mock, Gemini 또는 이후의 다른 Provider로 확장할 수 있습니다.

### 12-5. 현재 구현 결과

Android ARCore 앱과 FastAPI 서버, Mock AI, Gemini Provider 구조를 구현했습니다. 서버 단위 테스트 13개와 PC Mock HTTP E2E 13/13을 통과했습니다. 카메라·평면 인식, bbox 선택, Keyframe 생성, Job Polling, 결과 표시, TV·소파 프록시 배치, 전후 비교 코드가 준비돼 있습니다.

현재까지 확인한 것은 **시스템 연결 가능성**입니다. 실제 Gemini가 벽을 얼마나 자연스럽게 복원하는지, Android 실기기에서 Anchor가 얼마나 안정적인지, 실제 사용자가 2분 안에 과업을 완료하는지는 아직 검증하지 않았습니다. 이 세 항목을 다음 검증 목표로 두고 있습니다.

### 12-6. 기대하는 변화

ROOMSHIFT가 제공하려는 핵심 가치는 화려한 AI 이미지가 아닙니다. 사용자가 “무거운 가구를 옮기기 전에 내 공간의 변화를 직접 확인했다”고 느끼게 하는 것입니다. 이를 통해 사용자는 더 적은 시행착오로 가족과 배치안을 합의하고, 온라인 가구 구매나 실제 공간 변경을 더 확신 있게 결정할 수 있습니다.

### 12-7. 향후 확장

핵심 가설이 검증되면 다음 순서로 확장합니다.

1. bbox를 정밀 segmentation mask로 개선
2. 벽 복원 품질과 응답시간 최적화
3. 여러 배치안 저장·비교와 AI 추천
4. 실제 크기의 고품질 3D 가구와 충돌 처리
5. 벽지·바닥·조명 변경
6. 실제 판매 상품 및 구매 Journey 연결
7. 경량 On-device Model 또는 자체 복원 Engine 비교

### 최종 메시지

> **MISO ROOMSHIFT는 가구를 사기 전에 보여 주는 서비스가 아니라, 공간을 바꾸기 전에 먼저 경험하게 하는 서비스입니다.**
