# 시스템 구조 (PHASE 0 기준)

## 전체 구조

```text
┌───────────────────────────────┐
│  Android 앱 (Kotlin, ARCore)   │
│  - 카메라 / AR 공간 추적        │
│  - 벽 / 바닥 평면 인식          │
│  - 사물 선택 + 영역(bbox) 지정 │
│  - 대표 이미지(키프레임) 캡처   │
│  - 가구 프록시 배치/이동/크기   │
│  - 복원 결과 quad 를 벽에 고정  │
└───────────────┬───────────────┘
                │  키프레임(JPEG) + 메타(JSON) + 대상 영역
                ▼
┌───────────────────────────────┐
│  API 서버 (FastAPI)            │
│  - scene / keyframe 저장       │
│  - remove-object 작업 관리      │
│  - 외부 AI 어댑터 호출          │
│  - 가구 카탈로그 제공           │
│  - 호출 횟수 / 캐시 / 로그      │
└───────────────┬───────────────┘
                │  이미지 + 마스크 + 프롬프트
                ▼
┌───────────────────────────────┐
│  외부 AI 이미지 편집 API (A)   │
│  - "TV 제거 + 벽 복원" 인페인팅 │
└───────────────────────────────┘
```

저장은 해커톤 범위에서 로컬 파일 + SQLite 로 한다. 인증/큐/오브젝트 스토리지는 쓰지 않는다.

## A / B / C 전략

설계서 9장을 그대로 따른다. 우선순위 `A > B > C`.

| 방식 | 내용 | 이 실험에서 |
|---|---|---|
| A | 외부 AI 이미지 편집 API 로 삭제+복원 | **MVP 채택.** PHASE 1~5 |
| B | 온디바이스/로컬 경량 모델 | PHASE 6 실험 (별도 브랜치) |
| C | 다중 촬영 기반 자체 공간 복원 엔진 | PHASE 7 실험 (별도 브랜치) |

A 로 전체 기능을 먼저 완성하고, B/C 에서 품질이 나오는 부분만 나중에 교체한다.

## 외부 AI 어댑터

프로바이더는 아직 확정하지 않는다(TBD). 이미지 인페인팅/편집을 지원하는 서비스 중
해커톤 시점에 가장 빠르게 붙는 것을 쓴다. 서버는 다음 인터페이스로 추상화한다.

```text
RemoveObjectProvider.remove(image, mask, object_type, prompt) -> result_image
```

- 입력: 키프레임 이미지, 대상 마스크(또는 bbox→사각 마스크), 사물 종류, 프롬프트 문구
- 출력: 같은 해상도의 복원 이미지 + 변경 영역(bbox)
- 매 프레임 호출 금지. **사용자가 편집 명령을 실행할 때만** 1회 호출.
- 동일 `(keyframe_id, target)` 재요청은 서버 캐시에서 반환.

## 공간 고정 (Spatial Anchoring)

AI 결과는 2D 이미지다. 벽 평면(ARCore VERTICAL Plane)의 pose 를 기준으로 사각형 quad
메시를 만들고 결과 이미지를 텍스처로 입혀 벽에 고정한다. 카메라가 움직여도 quad 는
그 자리에 남는다. 카메라 각도 변화에 따른 정밀 보정(재투영)은 PHASE 3 범위.
