# 단지 추억 공유 소셜 AR — 웹 프로토타입

아파트 단지 입주민 전용 "추억 공유 소셜 AR"의 뼈대 프로토타입이다. 실제 AR Glass가 없는 상태에서, 단지 배치도 이미지(SVG) 위에 핀을 찍고 클릭하면 그 장소에 쌓인 게시물을 시간순으로 볼 수 있는 방식으로 핵심 컨셉을 먼저 검증한다.

## 핵심 컨셉

- CCTV처럼 자동 기록되는 것이 아니라, 입주민이 "이 순간을 남기고 싶다"고 직접 선택했을 때만 게시물이 생성된다.
- 촬영 장소와 게시 장소가 항상 같다 (단지 안에서 찍은 것을 그 자리에 게시).
- 같은 장소에 여러 시점의 기록이 쌓여 그 장소의 "시간 흐름"을 볼 수 있다.

## 실행 방법

```bash
npm install
npm run dev
```

`http://localhost:5173`(포트는 콘솔 출력 확인)로 접속한다. 별도 Backend/DB 없이 브라우저의 `localStorage`에 데이터가 저장되는 클라이언트 전용 구현이다.

```bash
npm run build   # 타입 체크 + 프로덕션 빌드
```

## 기술 스택

- React 19 + TypeScript + Vite
- 상태 관리: React Context (`src/state/AppContext.tsx`) + `localStorage` 영속화
- 별도 Backend/DB 없음 — 사진·영상은 `FileReader`로 Base64 Data URL 변환 후 `localStorage`에 저장
- 지도는 실제 지도 API 대신 인라인 SVG로 그린 단지 배치도(장식용 건물·산책로 포함)를 사용

이 기술 선택은 이 실험(Workstream)의 검증 대상이며, 프로젝트 전체 표준으로 간주하지 않는다. 자세한 내용은 `docs/workstreams/ar-memory.md` 참고.

## 구현된 기능

### 화면
1. **단지 지도** (`MapPage` + `SiteMap`): 게시물이 있는 5개 지점(중앙 벚꽃길, 어린이 놀이터, 공동 텃밭, 반려동물 산책로, 실개천 정자)에 핀 표시. 카테고리별 색상/이모지, 게시물 개수 배지.
2. **지점 타임라인** (`SpotTimeline`): 핀 클릭 시 해당 지점의 게시물을 시간순으로 나열. 같은 장소·다른 시점 기록을 비교하는 느낌을 주도록 세로 타임라인 UI로 표시.
3. **게시물 등록** (`PostForm`): 사진/영상 업로드, 카테고리 선택(계절 풍경/아이 성장/텃밭·화단/반려동물), 지도 클릭으로 위치(지점) 선택, 공개범위 선택(기본값: 이웃 공개).
4. **계정 전환 + 이웃 관리** (`AccountPage`): 테스트 계정 3개 전환, 이웃 맺기/해제.
5. **AR 체험 뷰** (`ARView`): 지도 화면의 "🥽 AR로 보기" 버튼을 누르면 전환되는 화면. 실제 AR Glass가 없는 상태에서 컨셉을 체감할 수 있도록, 놀이터의 실제 사진(`photo/playground.jpg`)을 배경으로 깔고 그 사진 속 세부 위치(미끄럼틀, 그네 등)에 핀을 띄운다. 핀은 지도 화면과 동일한 카테고리 색상 규칙을 따른다. 핀을 클릭하면 연결된 짧은 영상(5초 이내)이 팝업으로 재생되고, 영상이 없는 핀은 대신 사진/텍스트 카드가 뜬다. 현재는 배경 사진이 놀이터 한 장뿐이라 이 지점 고정으로 동작한다.

#### AR 마커(핀) 좌표 조정하기
`src/data/arMarkers.ts`의 `AR_MARKERS` 배열에서 각 핀의 `x`, `y`(배경 사진 기준 퍼센트 좌표, 좌상단이 0·0, 우하단이 100·100)를 직접 수정하면 된다. 사진을 보면서 원하는 위치의 퍼센트를 눈대중으로 잡아 넣으면 되고, 코드를 다시 빌드하거나 `npm run dev` 상태에서 저장하면 바로 반영된다.

#### AR 핀에 영상 연결하기
1. 5초 이내의 짧은 영상 파일(mp4 권장)을 `photo/` 폴더 바로 아래에 넣는다.
2. `src/data/arMarkers.ts`에서 해당 마커의 `videoFile`에 파일명을 적는다(예: `videoFile: "playground-slide.mp4"`).
3. 지정한 파일이 `photo/` 아래에 있으면 핀 클릭 시 그 영상이 재생되고, 없으면 `postId`로 연결된 게시물의 사진/텍스트 카드가 대신 표시된다.

**용량 주의**: 스마트폰으로 찍은 원본 영상은 대개 4K·수십 초 분량이라 그대로 넣으면 파일당 수십MB가 되어 Git 저장소에 부담이 된다. `photo/` 바로 아래에는 짧게 자르고(5초 이내) 웹용으로 압축한 최종 파일만 두고, 원본은 `photo/_source/`(Git에 커밋되지 않도록 `.gitignore`에 등록됨)에 보관하는 것을 권장한다. 압축 예시(ffmpeg):
```bash
ffmpeg -i 원본.mp4 -t 5 -vf "scale=960:-2" -c:v libx264 -preset slow -crf 26 -pix_fmt yuv420p -an photo/최종파일명.mp4
```

### 소셜 로직
- 이웃 맺기는 편도(팔로우형) 관계다. 테스트 계정 3개는 서로 다른 이웃 관계를 갖도록 시드되어 있어(김민준→이서연, 이서연→김민준·박도윤, 박도윤→이서연), 계정을 바꾸면 같은 지점이라도 보이는 게시물이 달라지는 것을 확인할 수 있다.
- 지점 타임라인 노출 규칙(`AppContext.getSpotPosts`):
  - 내 글, 내가 이웃 맺은 사람의 글: 공개범위와 무관하게 기본 노출.
  - 이웃이 아닌 사람의 "단지 전체 공개" 글: "더보기"로 분리 노출.
  - 이웃이 아닌 사람의 "이웃 공개" 글: 노출하지 않음.
- 좋아요/댓글은 게시물 카드에서 바로 가능하다.

### 시드 데이터
- 테스트 계정 3개(`src/data/seed.ts`)와 5개 지점에 걸친 15개 샘플 게시물을 기본 제공한다. 벚꽃길의 봄→여름→가을→겨울, 놀이터의 아이 성장, 텃밭의 심기→자라기→수확처럼 "같은 장소·다른 시점"을 바로 체감할 수 있도록 구성했다.
- 시드 게시물의 사진은 [Picsum Photos](https://picsum.photos)(API Key 없이 seed 문자열로 항상 같은 실제 사진을 반환하는 무료 Placeholder 이미지 서비스, `src/utils/media.ts`)를 사용해 실제 사진처럼 보이도록 채웠다. 지점·상황별로 고정된 seed를 써서 새로고침해도 같은 사진이 유지된다.
- 사용자가 직접 등록한 게시물은 `PostForm`에서 업로드한 실제 파일(사진/영상)이 Base64 Data URL로 저장되어 그대로 표시된다.
- 사진 표시는 `PostMedia` 컴포넌트가 시드/업로드 구분 없이 동일하게 `<img>`/`<video>`로 렌더링한다.

### AR 체험 뷰 배경 사진과 마커
- `photo/playground.jpg`는 Wikimedia Commons의 자유 라이선스 사진("Argos playground", 그리스 아르고스의 놀이터)을 웹 표시용으로 리사이즈(1600×900)한 것이다. 실제 AR Glass가 없는 상태에서 "배경 사진 위에 기록이 핀으로 떠 있는" 느낌을 보여주기 위한 예시 자산이며, 정식 서비스에서는 입주민이 직접 촬영한 단지 내 사진으로 대체되어야 한다.
- 사진 프레임은 이 사진의 실제 비율(16:9)로 고정되어 있어(`ARView`의 `.ar-view__frame`), 화면 크기와 무관하게 `src/data/arMarkers.ts`의 x/y 퍼센트 좌표가 항상 같은 지점을 가리킨다. 다른 비율의 사진으로 교체하면 이 값도 함께 맞춰야 한다.
- `photo/playground-slide.mp4`, `photo/playground-swing.mp4`는 실제 놀이터 영상을 5초로 자르고 웹용으로 압축(960px, H.264)한 예시 클립이다. 미끄럼틀·그네라는 이름과 정확히 일치하는 장면은 아니며, "핀을 클릭하면 영상이 재생된다"는 흐름을 보여주기 위한 임시 자산이다.

## 알려진 제약 (프로토타입 범위)

- 실제 인증 없음 — 테스트 계정 전환으로 로그인을 대신한다.
- Backend/DB 없음 — 모든 데이터는 브라우저 `localStorage`에만 저장되고 기기/브라우저 간 공유되지 않는다.
- 위치는 GPS/실제 지도 좌표가 아니라, 미리 정의한 5개 지점 중 선택하는 방식이다.
- 업로드 용량 제한, 이미지 압축 등은 처리하지 않는다.
- 시드 데이터의 사진은 외부 Picsum Photos CDN에서 불러오므로, 인터넷 연결이 없으면 시드 게시물 사진이 보이지 않을 수 있다(사용자가 직접 업로드한 사진은 영향받지 않음).
- 실제 AR(카메라 오버레이, 6DoF, 실시간 위치 정합)은 다루지 않는다 — `ARView`는 고정된 배경 사진 위에 미리 정의한 좌표의 핀을 얹은 정적 시뮬레이션이며, 배경 사진이 놀이터 한 장뿐이라 해당 지점 고정으로 동작한다.
- AR 마커는 놀이터의 미끄럼틀·그네 2곳만 정의되어 있고, 좌표는 눈대중으로 잡은 초기값이라 정밀하지 않다.
